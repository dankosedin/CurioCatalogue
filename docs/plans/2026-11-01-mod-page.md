# The mod page: screenshots and a generated ModDB description

Started 01.11.2026. The ModDB page (https://mods.vintagestory.at/curiocatalogue) gets screenshots in one style and in both
languages, and a description laid out as the best pages on the site do it, generated from the two READMEs. No change to the
mod itself. Research done 29.10–01.11.2026; its findings that the steps need are in Decisions below.

Replaces `ROADMAP.md`, 0.2, item 6 (screenshots): they are taken now with the current album, as a reproducible process; with
the stamp-album view of 0.2 the same shots are taken again, which checks how reproducible the process is.

## How to work on this plan

As in the previous plans: one step per short session with the project skill `/step <id>` (`.claude/skills/step/`). Each step
says **Branch**, **After**, **Model**, **Author** (a decision or in-game work only the author can do; "none" means the session
goes ahead on its own) and **Done when**. A session that stops in the middle writes one line under "Where we stopped".

The agent does not run the game: in-game work (building the scene, shooting, exporting icons) is the author's, with exact
commands and a checklist written by the agent. Nothing goes to ModDB without the author's "yes" to the exact text.

## Decisions

Before the plan (01.11.2026, research in the author's local notes):

- **Screenshots now, in this plan,** with the current album; the goal is a reproducible process (studio, macro, shot list,
  generator). On 0.2 the shots are taken again with the stamp-album view.
- **Only screenshots:** no video, no shader or texture packs (the player sees what the page shows). Frames 16:9, 1920×1080;
  no sky in a frame (clouds differ after a client restart, so `en` and `uk` frames would differ); if some gets in, the
  difference is ignored.
- **The description is generated.** README is the data, the generator adds the view: Markdig (README → data), Scriban (the
  template), PreMailer.Net (CSS → inline `style`). README stays plain Markdown without HTML for layout. Rejected: a separate
  hand-written HTML file (four sources of the texts instead of two, they drift apart); styles written in the generator's code
  (design in C# instead of HTML/CSS); YAML as the source of README and the page (README is edited by hand and read in the
  players' rounds).
- **The generator is a CakeBuild task,** not a separate file-based app: CakeBuild is already there, as a task in Gradle.
- **The Ukrainian hook** is the first paragraph of `README.uk.md`, as the English one is of `README.md` (`modinfo.json` has
  only English).
- **PNG or JPEG** is decided in P3 on a real frame of the full scene.

Studio (02.11.2026):

- **The studio and the macros live in the repo, in `tools/studio/`:** the scene as a WorldEdit schematic (`/we export`,
  JSON), the macros as the game's JSON files in `tools/studio/macros/`, and the recipe to rebuild the world in
  `docs/screenshots.md` (superflat, `/we import` at a fixed point, time and weather). The macros' `.cam` coordinates are
  absolute, so the import point is fixed and written down. Anyone (a translator too) can rebuild the studio and shoot their
  language. A copy of the world file stays on the author's machine for convenience, not as the source. Rejected: the world
  file (`.vcdbs`, ~9 MB SQLite) in git (every save rewrites the whole file, no diff, the history grows); the world file
  outside the repo only (nobody else can rebuild the studio); Git LFS or a GitHub Release asset (a tool or a public action
  for one file). To check in P2: the schematic carries the chest's contents and the books' attributes; if the books lose
  their state, the recipe fills them after the import.

Studio, built (03.11.2026, P2):

- **Checked:** the schematic carries the chest's contents and the books with their data into a new world with the same
  mods, so the recipe does not refill the books. The entries' item ids are not remapped by the game (a tree array), so
  this holds only with the same mod set (`docs/testing/commands.md`, WorldEdit).
- **The studio uses only vanilla blocks.** A building mod (chisel tools) was tried and dropped: a mod in the studio's
  world could shift the item ids, and everyone who rebuilds the studio would need it.
- **The import point is fixed by absolute coordinates** (`/we mark =512010 =3 =512010 …`), not by where the player
  stands; the rebuild is one macro (Alt+0, `tools/studio/macros/10-studio-rebuild.json`) with time and weather. The
  `.cam` points are taken in the rebuilt world.
- **The tapestry wall shows what the album is missing:** different pictures, some complete, some with a plank frame in a
  missing piece's place. The title card puts the album's window beside the wall. Rejected: one picture repeated (it reads
  as wallpaper, not a collection).
- **The shot list is approved** as written in `docs/screenshots.md`; first the studio's base, the details of each shot
  with its macro.
- The sky through the leaded windows stays: the glass hides it enough; only a large own window would need a fix.
- **Props live in the studio's trunks** and go into the schematic with them: a rebuilt world has them ready; a prop a
  shot changes has its own copy. Rejected: macros that give blank books and pieces (longer, and the result depends on
  the order of the gestures).
- **One cover, `darkgreen`,** for every book in the shots and for the icons of P4: it exists both normal and aged (teal,
  the first choice, has no aged variant).
- **`materials` shows the bill of materials' intake list** from a handbasket (planks and resin, with counts), not
  the book's window: the book in the props is empty (nothing posted into it), so its window shows nothing. Redone when
  the bill of materials gets recipes. `ledger-intake` is the ledger's intake list from the chest (tapestries).
- **`first-ledger` has the inventory in the centre:** on "auto" it opens on the right; the dragged position is kept in
  `tools/studio/dialog-positions.json` with the one for `title`.
- **The test frames of P2 stay outside the repo** (the author's screenshots folder, 03.11.2026, 17:42–18:02): the files
  in `docs/images/` come from P3's script, named and checked.
- **Good enough now** (03.11.2026): the album's and the lists' windows are plain today, so the shots are taken as they
  are (a bill of materials with two entries, no sorting, no tooltip on `first-ledger`) and polished when there is more
  to show (the stamp-album view of 0.2).
- **Windows on "auto", except `title`:** a dragged window is remembered by its dialog name (`clientsettings.json`,
  `dialogPositions`), and all our books share one (`curiocatalogue-ledger`). In `title` the album's window is on the
  left, the wall on the right (draft 17-18-16): a centred window, tried first, covers the wall. The position is kept in
  `tools/studio/dialog-positions.json`, written by the script of P3; `title` is shot first, then the album window goes back to "auto" in game.
- **The title card's text is a slanted ribbon of two or three words** across a corner, like the ribbons on ModDB pages;
  the words are P5's. So the frame needs only a corner of plain brick, not a free third.

Title card (03.11.2026):

- **The title card's text is drawn by a script** (`tools/screenshots.ps1`, P3) on a frame shot without text: reproducible
  in every language and in one style. Rejected: a sign in game (the game's font is unreadable at the gallery's ~800 px; a
  second sign or an edit between the `en` and `uk` shots); an image editor (a manual step, repeated on 0.2 and by every
  translator). The font: a free-licensed one kept in the repo, or a system one (P3).
- **The page does not repeat itself:** the same text twice in a row (on the title card and as the description's first
  paragraph) is a sign of poor quality. So the title card's text is not necessarily README's first paragraph, or that
  paragraph is not rendered into the description; P5 decides which.

Layout research (31.10–01.11.2026: 65 pages of the site by downloads, novelty, updates and follows; 19 pages the author likes;
the best of both looked at in a browser):

- The first screen of a ModDB page is the gallery (first image ~800×516, ratio ~1.55; narrower images get grey bars) and the
  download card; the description starts below the fold. So "what the mod does, in five seconds" is the gallery's first
  image: the best pages put a title card or a picture of the mechanic there. Ours showed a chest on grass.
- The description runs the full width of the window; good pages put it into a centred card (`max-width` ~960 px).
- Four layouts on good pages: a hero card on top (name, hook, two or three sentences, badges, a picture); a table "icon —
  description" (64 px icons); accordions for long sections (`<details>` or ModDB's spoiler); plain headings and lists.
  Ours: a hero, an icon table for the books and lists, accordions for the rest, the whole Ukrainian version in one
  `<details>` under the badges instead of the second half of the page.
- Only our page is bilingual on the whole sample.

Layout test (01.11.2026, a hand-written page in the draft mod, desktop Chrome and the author's phone):

- ModDB keeps inline `style` verbatim (`flex`, `gap`, `flex-wrap`, `max-width`, `box-shadow`, `border-radius`,
  `scroll-margin-top`), `<details>` / `<summary>` (nested too; `open` becomes `open="open"`), tables, `<code>` and every `id`.
  It drops `<style>`, so CSS must be inline; media queries, hover and pseudo-elements cannot be inlined, so the layout uses
  none (`flex-wrap` and `flex-basis` are enough: on the phone the hero's image goes under the text, no horizontal scroll).
- **HTML comments are escaped and shown as text:** the generator removes them.
- An anchor on a `<details>` only scrolls; Chrome opens a closed `<details>` when the target is inside it, so the `id` goes on
  an inner block with `scroll-margin-top`.
- The books' textures (`textures/item/book-*.png`) are only the label on the cover, so book icons come from the game's render
  (P4); the lists' textures are whole.

Shooting (engine 1.22.7 decompiled, checked in game 01.11.2026, superflat creative, `uk` → `en`):

- `.cam p` adds a point with position and angle; `.cam save` copies the points as text (absolute coordinates: valid only in
  that world), `.cam load <text>` replaces the list, `.cam goto 0` restores position and angle exactly (frames match pixel for
  pixel). Creative or spectator only. The wiki's command pages are from 1.15; where they differ, the code is right.
- Macros (Ctrl+M): a name, a list of commands (both `.` and `/`) and a key; they survive a restart and a language switch.
  The editor wraps long lines and saves them wrapped, which breaks `.cam load …`: write long commands into
  `VintageStory-DevData\Macros\<n>-<code>.json` while the editor is closed, then restart the client.
- `/time stop`, `/weather setprecip -1`, `/weather acp` are stored in the world: set once when building the studio. `/time set
  …` moves to the next day each time, so it is not in the macro either.
- HUD: F4 / `.gui false` hide the whole 2D layer, windows included. For frames with a window, hide parts: `.cf showMinimapHud
  false`, `showCoordinateHud`, `showBlockInfoHud` (apply at once, survive a restart); the chat hides itself after 15 s without
  messages; "Need help…" goes by holding K. The hotbar and the health bars stay; the crosshair hides while a window is open;
  do not look at a block (its selection frame).
- `.resolution 1080p` gives exactly 1920×1080 in a window but does not survive a restart (so it is in the macro). F12 saves to
  `Pictures\Vintagestory`; Ctrl+F12 doubles the size (too big). Keep the GUI scale at 100 %.
- Size: an empty field 1.6 MB, a field with an open album and clouds 1.79 MB; a full scene is likely over 2 MB (P3 decides
  the format).
- `.exponepng hand 128` writes the held item's icon with a transparent background to `VintageStory-Dev\icons\block\<code>.png`;
  the name has no cover variant, so the next export overwrites it: take it at once.
